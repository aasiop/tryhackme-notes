# Networking Secure Protocols

--- 
### TLS

**TLS (Transport Layer Security)** - allows secure communication between a client and a server over an insecure network. TLS ensures that no one can read or modify the exchanged data. Encrypts data. Newest version is ==TLS 1.3==.

A **TLS certificate** is used to prove the identity of a server or client. Process od getting one:
- The administrator creates a **CSR (Certificate Signing Request)** and sends it to a **CA (Certificate Authority)**.
- The CA verifies the request and issues a **signed certificate**.
- Devices use now trusted CA certificates to verify the certificate's validity.

> Self signed certificate should not be used to confirm the authenticity of a server

**SSL (Secure Sockets Layer)** - older and less secure than a TLS certificate. Authenticates a website's identity and enables an encrypted connection.

### HTTPS

HTTP needs only to establish a TCP three-way handshake with the target server. While HTTPS needs also establishing a TLS session.

---

### SMTPS, POP3S, IMAPS

It is similar to HTTPS. It is adding s (secure) to the TLS to SMTP, POP3. Adds establishing TLS connection. However ports numbers change:

1. ***OLD***:
- **HTTP**- 80
- **SMTP** - 25
- **POP3** - 110
- **IMAP** - 143
1. ***NEW***:
- ***HTTPS*** - 443
- **SMTPS** - 465 and 587
- **POP3S** - 995
- **IMAPS** - 993

### SSH

**SSH (Secure Shell)** - A more secure version of telnet.  Supports password-based authentication and public key and two-factor authentication. Also OpenSSH provides end-to-end encryption. OpenSSH is open-source implementation of the SSH protocol. 

**SSH commands**:

| Command                                                            | Description                             |
| ------------------------------------------------------------------ | --------------------------------------- |
| `ssh [username]@[site.org] -p [port]`                              | logs using ssh on specific port         |
| `ssh -i [path_to_key]/key.private [username].[site.org] -p [port]` | logs using private key on specific port |

---

### SFTP, FTPS

**SFTP (SSH File Transfer Protocol)** - allows secure file transfer via SSH. Shares ==port 22==. If enabled in the OpenSSH server configuration, you can connect using a command such as `sftp username@hostname`.

**FTPS (ile Transfer Protocol Secure)** - allows secure file transfer via TLS. Shares ==port 990== (ftp used 21). 

---

### VPN

**VPN (Virtual Private Network)** - allows different offices or users to connect securely over the Internet as if they were on the same private network.Creates an encrypted **VPN tunnel** between a VPN client and a VPN server.

**How VPN Works**:

- The **VPN client encrypts** traffic and sends it through the VPN tunnel.
- The **VPN server decrypts** the traffic and forwards it to the destination.
- When all traffic is routed through the VPN, websites see the VPN server's public IP address, not the user's real IP.
