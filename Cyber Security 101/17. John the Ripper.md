# John the Ripper

### Basics

**John the Ripper** - is a free, open-source software tool used to recover or crack the passwords from encrypted hashes. Most popular version of John the Ripper is **Jumbo John**.  

Basic John syntax:
```bash
john [options] [file path]
```

---
### Automatic Cracking

John has built-in features to detect what type of hash. But we can use more unreliable way to crack hashes (automatic):

```bash
john --wordlist=[path to wordlist] [path to file]
```

---

To identify hash we can use:
- website: https://hashes.com/en/tools/hash_identifier

---
### Format-Specific Cracking

After identifying hash, we can use:
```bash
john --format=[format] --wordlist=[path to wordlist] [path to file]
```

Example:
```bash
john --format=raw-md5 --wordlist=/usr/share/wordlists/rockyou.txt hash_to_crack.txt
```

> use prefix raw- to use standard hash type. Check if you need to add prefix or not: `john --list=formats` or `john --list=formats | grep -iF "md5"`

### Cracking Linux

Linux hash files are stored in the /etc/shadow file.   
First we need to unshadow file:
```bash
unshadow [path to passwd] [path to shadow]
```
example:
```text
unshadow local_passwd local_shadow > unshadowed.txt
```
- `[path to passwd]`: The file that contains the copy of the `/etc/passwd` file you’ve taken from the lab machine
- `[path to shadow]`: The file that contains the copy of the `/etc/shadow` file you’ve taken from the lab machine
Then we can crack:
```bash
john --wordlist=[path to wordlist] --format=sha512crypt unshadowed.txt
```
>In most examples you don't need to use --format for shadow hashes

### Single Crack mode

**Single Crack mode** - it does not require a large wordlist to find passwords. Instead, it generates password guesses automatically using only the information already available in your target file, by slightly changing the letters and numbers contained within the username.  

**GECOS (General Electric Comprehensive Operating System)** - It stores general information about the user, such as the user’s full name, office number, and telephone number, etc.. John uses this information to add words to the wordlist.

Usage:
```bash
john --single --format=[format] [path to file]
```
Example:
```bash
john --single --format=raw-sha256 hashes.txt
```

> When using file formats in Single Crack mode, you need to change file format from this:  
> 1efee03cdcb96d90ad48ccc7b8666033, to this:  
> mike:1efee03cdcb96d90ad48ccc7b8666033

### Custom Rules

If we want to enhance Single Crack Mode ideas, we can add **custom rules**. Custom Rules are also helpful when passwords a particular pattern (e.g. must include lowercase letter, uppercase letter, number and symbol). Custom rules can be added to file at path: `/usr/share/john/john.conf` on Kali Linux.  

Adding custom rules: (example)
1. First define name of your rule (add line to file): `[List.Rules:THMRules]` (we will use it to call our custom rule)
2. Define how the original word should be modified using different **modifiers**. The most common ones are:
	- `Az` – appends characters to the end of the word
	- `A0` – prepends characters to the beginning of the word
	- `c` – capitalises the first letter of the word
3. Define which characters should be added using **character sets** inside square brackets `[ ]`:
- `[0-9]` – any number from 0 to 9
- `[A-Z]` – uppercase letters
- `[a-z]` – lowercase letters
- `[A-z]` – uppercase and lowercase letters
- `[!£$%@]` – one of the specified symbols
- `[0]` – only the number 0
- `c` - capitalises the first letter

Example:
```text
[List.Rules:PoloPassword]
cAz"[0-9] [!£$%@]"
```

Utilises the following:

- `c`: Capitalises the first letter
- `Az`: Appends to the end of the word
- `[0-9]`: A number in the range 0-9
- `[!£$%@]`: The password is followed by one of these symbols

Running command with rules: (example)
```bash
john --wordlist=[path to wordlist] --rule=THMRules [path to file]
```

### Cracking Password Protected Zip Files

Similarly to the `unshadow` tool we used previously, we will use the `zip2john`:
```bash
zip2john [options] [zip file] > [output file]
```
> options shouldn’t often be necessary

Example:
```bash
zip2john zipfile.zip > zip_hash.txt
```

Then with zip_hash we can crack:
```bash
john --wordlist=/usr/share/wordlists/rockyou.txt zip_hash.txt
```

Unziping file:
```bash
unzip [file].zip
```

---

### Cracking Password Protected RAR Files

Identical to zip2john:
```bash
rar2john [rar file] > [output file]
```

We can unrar file with command:
```bash
unrar x [file].rar
```

### Cracking SSH Key with John

```bash
ssh2john [id_rsa private key file] > [output file]
```

Cracking:
```
john --wordlist=/usr/share/wordlists/rockyou.txt id_rsa_hash.txt
```
