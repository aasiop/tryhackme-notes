# Gobuster Basics

### Basics

**Gobuster** - an open-source offensive tool written in Golang. It **enumerates (lists all available , whether they are accessible or not)** web directories, DNS subdomains, vhosts, Amazon S3 buckets, and Google Cloud Storage by brute force, using specific wordlists and handling the incoming responses.

### Commands

Use `gobuster --help` for helpful help page.  
You can use also `gobuster [command, e.g. dir] --help` for extensive help for specific command.

Flags:

| Flag    | Description                                                                    |
| ------- | ------------------------------------------------------------------------------ |
| -t      | configures the number of threads to use for the scan                           |
| -w      | configures a wordlist to use for iterating                                     |
| --delay | defines the amount of time to wait between sending requests (bypass detection) |
| --debug | troubleshoot errors                                                            |
| -o      | writes the enumeration results to a file                                       |
There are a lot more flags. There is no need to remember them all. Just use help command.

Example command:

a) dir:

```bash
gobuster dir -u "http://www.example.thm/" -w /path/to/wordlist.txt -t 64
```

- `gobuster dir` indicates that we will use the directory and file enumeration mode.
- `-u "http://www.example.thm/"` target URL
- `-w /usr/share/wordlists/dirb/small.txt` directs Gobuster to use the _small.txt_ wordlist to brute force the web directories. Gobuster will use each entry in the wordlist to form a new URL and send a GET request to that URL.
- `-t 64` sets the number of threads Gobuster will use to 64. This improves the performance drastically.

b) dns:

```bash
gobuster dns -d example.thm -w /path/to/wordlist.txt
```

- `gobuster dns` enumerates subdomains on the configured domain.  
- `-d example.thm` sets the target to the _example.thm_ domain.  
- `-w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt` sets the wordlist. Gobuster construct a new DNS query

c) vhost (Virtual hosts are different websites on the same machine):

```bash
gobuster vhost -u "http://example.thm" -w /path/to/wordlist.txt
```

more practical example:

```bash
gobuster vhost -u "http://10.114.162.172" --domain example.thm -w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt --append-domain --exclude-length 250-320
```

- `gobuster vhost` instructs Gobuster to enumerate virtual hosts.
- `-u "http://10.114.162.172"` sets the URL to browse to 10.114.162.172.
- `-w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt` configures Gobuster to use wordlist
- `--domain example.thm` sets the top- and second-level domains in the `Hostname:` part of the request to _example.thm._  
- `--append-domain` appends the configured domain to each entry in the wordlist. If this flag is not configured, the set hostname would be _www_, _blog_, etc. This will cause the command to work incorrectly and display false positives.
- `--exclude-length` filters the responses we get from the sent web requests. With this flag, we can filter out the false positives. If you run the command without this flag, you will notice you will get a lot of false positives like "Found: Orion.example.thm Status: 404 [Size: 279]" or  "Found: pm.example.thm Status: 404 [Size: 276]". These false positives typically have a similar response size, so we can use this to filter out most false positives. We expect to get a 200 OK response back to have a true positive.

> www.example.thm -> www (subdomain), .example (second-level domain), .thm (top-level domain)
