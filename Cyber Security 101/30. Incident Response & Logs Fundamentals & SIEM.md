
# Incident Response & Logs Fundamentals

### Incident Response

**Incident Response (IR)** is the process of preparing for, detecting, responding to, and minimizing the impact of cybersecurity incidents. It covers an incident **from detection to resolution**.

--
### Alerts & Incidents

- **Event:** Any activity generated and logged by a process on a device.
- **Alert:** A security solution identifies an event/group of events as potentially harmful.
- **False Positive:** An alert appears malicious but is actually legitimate.
- **True Positive:** An alert correctly identifies harmful activity.

---
### Common Incident Types

- **Malware Infection:** malicious software damages or compromises systems.
- **Security Breach:** unauthorized access to confidential data.
- **Data Leak:** confidential information is exposed to unauthorized parties; can be intentional or caused by human error/misconfiguration.
- **Insider Attack:** an attack initiated by someone inside the organization, often dangerous because insiders already have access to resources.
- **DoS (Denial of Service):** flooding a system/network/application with requests until resources are exhausted and legitimate users cannot access it.

---
### Playbooks & Runbooks

- **Playbook:** a comprehensive guideline describing how to respond to a particular type of incident.
- **Runbook:** detailed, step-by-step instructions for executing specific actions during incident response.

**Key distinction:** A **playbook** describes the overall response strategy; a **runbook** provides detailed execution steps.

---

### Logs

**Logs** - digital footprints of activities performed on systems

---
### Types of Logs

- **System Logs:** OS activities, startup/shutdown, drivers, hardware and system errors.
- **Security Logs:** authentication, authorization, account changes, security policies and suspicious activity.
- **Application Logs:** application activity, updates, errors and user interactions.
- **Audit Logs:** data access, system changes, user activity and policy enforcement.
- **Network Logs:** incoming/outgoing traffic, network connections and firewall activity.
- **Access Logs:** access to web servers, databases, applications and APIs.

---
### Windows Event Viewer

**Event Viewer** is the built-in Windows GUI used to view, search and filter event logs.

Important event fields:

- **Description** – details of the activity.
- **Log Name** – name of the log.
- **Logged** – time of the event.
- **Event ID** – unique identifier for a specific activity

---

### SIEM

**SIEM** (Security Information and Event Management) -   a core SOC solution that **collects, normalizes, correlates and analyzes logs** from different sources to detect malicious activity.

> SIEM turns large amounts of scattered logs into centralized, correlated and actionable security information.

---
### Network-Centric

Logs generated by **network communication**:

- SSH co nnections
- FTP activity
- Web traffic
- VPN access
- Network file sharing

Examples: **firewalls, IDS/IPS, routers**.

---
## Main SIEM Features

- **Centralized Log Collection:** gathers logs from endpoints, servers, firewalls, etc. into one location.
- **Parsing:** breaks raw logs into individual fields.
- **Normalization:** converts logs from different sources into a **consistent format**.
- **Correlation:** connects events from multiple sources to identify suspicious patterns.
- **Real-time Alerting:** detection rules trigger alerts when specific conditions are met.
- **Dashboards & Reporting:** provide summarized, actionable information such as failed logins, triggered rules, alerts and visited domains.

---
### Common Log Locations

### Windows

Windows logs can be viewed using **Event Viewer** and contain unique Event IDs for activities.

### Linux

Common locations:

- `/var/log/httpd` – HTTP requests/responses and errors
- `/var/log/cron` – cron jobs
- `/var/log/auth.log` / `/var/log/secure` – authentication
- `/var/log/kern` – kernel events
    

### Web Servers

Apache logs are commonly stored in:

- `/var/log/apache`
    
- `/var/log/httpd`

## Log Ingestion Methods

1. **Agent/Forwarder** – lightweight software installed on endpoints sends logs to SIEM.
2. **Syslog** – protocol for sending logs to a centralized destination.
3. **Manual Upload** – offline logs can be uploaded for analysis.
4. **Port Forwarding** – endpoints send logs to a SIEM listening on a specific port.
    

### Important Examples

- **Event ID 104** + WinEventLog → **Event Log Cleared**
    
- **Event ID 4688** + `NewProcessName` contains `whoami` → **WHOAMI command execution detected**
    

Detection rules depend on **field-value pairs**, which is why normalized logs are important.
