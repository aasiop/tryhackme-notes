# Public Key Cryptography

### Basics

- **Authentication**: You want to be sure you communicate with the right person, not someone else pretending.
- **Authenticity**: You can verify that the information comes from the claimed source.
- **Integrity**: You must ensure that no one changes the data you exchange.
- **Confidentiality**: You want to prevent an unauthorised party from eavesdropping on your conversations.

We can use analogies for cryptographic system:
- lock - public key
- lock's key - private key  
>The public key is known to all correspondents and is used for encryption, while the private key is protected and used for decryption

---
### RSA

RSA is a public-key encryption algorithm that enables secure data transmission over insecure channels. RSA is based on the mathematically difficult problem of factoring a large number.

---

### Diffie-Hellman Key Exchange

**Diffie-Hellman** - allows two parties to establish a **shared secret over an insecure channel**. Process:

1. Alice and Bob agree on public values `p` (large prime) and `g` (generator).
2. Alice chooses private `a`; Bob chooses private `b`.
3. They calculate public keys:
    - `A = g^a mod p`
    - `B = g^b mod p`
4. They exchange `A` and `B`.
5. Both calculate the same shared secret:
    - Alice: `B^a mod p`
    - Bob: `A^b mod p`

### SSH

1. **Authenticating Server:**
   When connecting to an unknown SSH server, the client shows the server's public key fingerprint, if it didn't match server asks to connect:  
   ```
   The authenticity of host '10.10.244.173 (10.10.244.173)' can't be established. ED25519 key fingerprint is SHA256:lLzhZc7YzRBDchm02qTX0qsLqeeiTCJg5ipOT0E/YM8. This key is not known by any other name. Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
   ```
2. **Authenticating Client**:
   SSH can authenticate users with:
   - Username + password
   - Public/private key pair

#### Commond SSH key types:

| Type                                               | Description                        |
| -------------------------------------------------- | ---------------------------------- |
| rsa                                                | RSA key                            |
| DSA (Digital Signature Algorithm)                  | Public-key cryptography algorithm  |
| ECDSA (Elliptic Curve Digital Signature Algorithm) | Elliptic Curve DSA                 |
| ECDSA-SK (ECDSA with Security Key)                 | ECDSA with hardware security key   |
| Ed25519                                            | Modern public-key signature system |
| Ed25519-SK (Ed25519 with Security Key)             | Ed25519 with hardware security key |
> To generate key pair with default options, use: `ssh-keygen -t [key type, e.g.: ed25519]`

### Digital Signature and Certificates

**Digital Signature**- verifies the authenticity and integrity of a digital document or message.  

**Certificate** - binds a **public key** to an identity and is used to verify trusted entities, e.g. websites with HTTPS.  

---
### PGP
**PGP (Pretty Good Privacy)** - software for **encryption** and **digital signatures**.  

**GPG (GnuPG)** - open-source implementation of the OpenPGP standard.  

Commands:

| Command                                | Description                 |
| -------------------------------------- | --------------------------- |
| gpg --full-gen-key                     | shows menu to generate keys |
| gpg --import [key_name].key            | imports key                 |
| gpg --decrypt confidential_message.gpg | decrypts messge             |

### Some definitions

- **Cryptography** is the science of securing communication and data using codes and ciphers.
- **Cryptanalysis** is the study of methods to break or bypass cryptographic security systems without knowing the key.
- **Brute-Force Attack** is an attack method that involves trying every possible key or password to decrypt a message.
- **Dictionary Attack** is an attack method where the attacker tries dictionary words or combinations of them.
