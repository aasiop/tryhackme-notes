# Nmap Advanced Port Scans

### More new scans

- **Null scan (-sN)** - it is a tcp packet with no flags (doesn't trigger any response when reaches open port)
- **FIN Scan (-sF)** - a tcp packet with FIN flag. No response will be sent if the TCP port is open
- **Xmas scan (-sX)** - similar to null and fin

> One scenario where these three scan types can be efficient is when scanning a target behind a stateless (non-stateful) firewall.

>Non-stateful firewall (stateless) track every packet **independently** of any others. While Stateful tracks state and context of **entire** connection

- **TCP ACK Scan (-sA)** - scan useful for discovering firewall rule sets
- **Windows Scan (-sW)** - scan useful for discovering firewall rule sets
- **Custom Scan (--scanflags CUSTOM_FLAGS)** - yea

### Spoofed IP scan

Spoof IP scan is a scan where an attacker disguises their identity by forging the source IP address. This scan is only beneficial when you can guarantee that you will capture the response. Attacker needs to monitor the network traffic to analyse the replies.

![nmap1.png](screenshots/nmap1.png)

Example usage:
```bash
nmap -S SPOOFED_IP MACHINE_IP
```

In general, you expect to specify the network interface using `-e` and to explicitly disable ping scan `-Pn`:
```bash
nmap -e NET_INTERFACE -Pn -S SPOOFED_IP MACHINE_IP
```

### Fragmented packets

Adding `-f` or `-ff` to nmap fragments packet (devides data to more packets). Only helps with dealing with old firewalls or useful when testing IDS software.

---

### Idle/Zombie Scan

**Idle/Zombie Scan (-sI ZOMBIE_IP)** - Nmap will make each probe appear to come from the idle (zombie) host, then check whether the idle (zombie) host received any response to the spoofed probe. This is like spoofed IP scan but you don't need to listen for connections.
