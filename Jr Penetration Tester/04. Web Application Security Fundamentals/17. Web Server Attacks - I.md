# Web Server Attacks - I

### Identifying Web Servers

```bash
# -s suppresses the progress bar
# -I sends a HEAD request, returning only response headers
curl -sI http://MACHINE_IP:80
```

| Port | Server             | Default Server Header          |
| ---- | ------------------ | ------------------------------ |
| 80   | Apache2            | `Apache/2.4.x (Ubuntu)`        |
| 8000 | Python HTTP Server | `SimpleHTTP/0.6 Python/3.xx.x` |
| 3000 | Node.js Express    | None (set by application)      |
| 8080 | Nginx              | `nginx/1.xx.x`                 |

> Some frameworks add an `X-Powered-By` header that reveals the application layer behind the server. Example `X-Powered-By: Express`

> DevTools provides the same header information without any additional tools

### Python HTTP Server

Simple python server to quickly share files:
```bash
# This command serves the current working directory over HTTP on port 8000
python3 -m http.server 8000
```

> It is important that this quick file shares often remain "accidentally exposed to the internet for six months". Easy to exploit

Accessing Dotfiles, example:
```bash
curl -s http://10.114.147.123:8000/.env
```

> If the directory shows an `index.html` file, Python will serve that file instead of showing the directory listing. If you do not see a directory listing at the root, try requesting paths directly or navigating to subdirectories.

### Apache2

**Apache** - the most widely deployed web server in the world. Its default Ubuntu configuration leaves several things enabled that testers regularly find and report. The three most common are:
- directory listing on specific paths
- the `server-status` module
- backup files sitting in the document root.

1. Directory Listing:

	Apache's `Options +Indexes` directive tells the server to display a file listing when a directory does not have an `index.html`.
	
> 	Its something like dotfiles.

2. Server_status Page:
	
	example:
	```http
	http://10.112.166.59:80/server-status
	```
3. Finding Unlinked Files (forgotten test files, old copies, etc.):
	
	```bash
	# -u is the target URL
	# -w is the wordlist path
	# -x tells gobuster to also append these extensions to each word
	gobuster dir -u http://TARGET_IP:80 -w /usr/wordlists/common.txt -x bak,txt,html -t 20
	```
	Look for files like: `.bak`, `.htpasswd`,

### Node.js (Express)

Node.js - open-source runtime environment that allows you to execute JavaScript code on a computer or server, outside of a web browser.

```bash
curl -sI http://10.112.166.59:3000
```

When you see `X-Powered-By: Express` (unless developer disables it) it shows that app is using Express.

---

1. Reading the Application Version:
	```bash
	curl -s http://10.112.166.59:3000
	```
	
2. Triggering Verbose Errors:
	Trigger errors to reveal internal paths, database information, SQL queries, and stack traces.
	```bash
	curl -s http://TARGET_IP:3000/api/users | python3 -m json.tool
	```
> Look for: `500 Internal Server Error`, `stack`, `ECONNREFUSED`, internal file paths.

3. Debug Endpoints (Route Enumeration):

	Developers sometimes leave endpoints that list all registered routes.
	```bash
	curl -s http://TARGET_IP:3000/api/routes
	```
> Example routes: `/api/users`, `/api/routes`, `/api/debug/env`, /static/config.js

### Nginx

**Nginx** - a high-performance web server commonly used as a reverse proxy, load balancer, or static file server.

1. Read Version:
Nginx exposes its version through the `Server` header by default.

```bash
curl -sI http://TARGET_IP:8080 | grep -i server
```

Example: `Server: nginx/1.24.0 (Ubuntu)`
2. Directory Listing (Autoindex):
```bash
curl -s http://TARGET_IP:8080/files/
```
3. Exposed Status Page:
```bash
curl -s http://TARGET_IP:8080/nginx_status
```

### Security Headers

| Header                      | What It Protects Against                                                            | Example Value                    |
| --------------------------- | ----------------------------------------------------------------------------------- | -------------------------------- |
| `X-Frame-Options`           | Clickjacking (prevents the page from being embedded in an iframe on another domain) | `DENY` or `SAMEORIGIN`           |
| `X-Content-Type-Options`    | MIME sniffing (prevents the browser from guessing content types)                    | `nosniff`                        |
| `Content-Security-Policy`   | Restricts where scripts, stylesheets, and other resources can load from             | `default-src 'self'`             |
| `Referrer-Policy`           | Controls what is sent in the `Referer` header when navigating to another page       | `no-referrer` or `strict-origin` |
| `Strict-Transport-Security` | Forces HTTPS for subsequent requests (only meaningful on HTTPS servers)             | `max-age=31536000`               |
> When missing reveals misconfigurations.

### Patterns

|Misconfiguration|Apache|Python HTTP|Node.js|Nginx|
|---|---|---|---|---|
|Version disclosure in headers|Yes|Yes|Partial|Yes|
|Directory listing|`/files/`|Root path|N/A|`/files/`|
|Exposed status or debug endpoint|`/server-status`|N/A|`/api/debug/env`, `/api/routes`|`/nginx_status`|
|Sensitive files accessible|`backup.bak`, `internal-notes.txt`|`.env`, `notes.txt`, `backup.zip`|`config.js`|`server-config.txt`, `deploy-notes.txt`|
|Missing security headers|All|All|All|All|
